# Архитектура и состояние проекта

## Модули

| Файл | Ответственность |
| --- | --- |
| `index.html` | Панели, меню, инструменты и SVG-поле |
| `style.css` | Компоновка, оформление и адаптация интерфейса |
| `app.js` | Точка входа: запуск редактора |
| `editor/controller.js` | Действия пользователя, выделение, жизненный цикл жестов и запуск пересчёта |
| `editor/renderer.js`, `editor/symbols.js` | SVG, панели, кеш геометрии и символы компонентов |
| `editor/dom.js`, `editor/render-scheduler.js` | Обновление изменившихся DOM-элементов и объединение перерисовок |
| `editor/history.js` | Независимые снимки схемы и сигналов для undo/redo |
| `editor/storage.js` | localStorage и файловый импорт/экспорт |
| `editor/viewport.js` | Координаты, масштаб, обзор и вписывание схемы по габаритам компонентов |
| `components.js` | Типы компонентов, список пинов и настраиваемое число входов, допустимые сигналы |
| `circuit.js` | Индексы компонентов/пинов, валидация и формат документа |
| `simulator.js` | Вычисление сигналов и распространение; прежние экспорты TYPES/validate сохранены |
| `geometry.js` | Сетка, координаты пинов, габариты корпуса, ортогональные маршруты, точки ответвлений и попадания в рамку выделения |
| `examples.js` | Полусумматор и RS-триггер на NOR |
| `tests/` | Автоматические проверки логики, импорта и геометрии |
| `scripts/check-browser.mjs` | Проверки интерфейса через Chrome DevTools Protocol |

Приложение загружается браузером как нативные ES modules. Сервер Python раздаёт статические файлы; бэкенда и сборки нет. Модули симуляции и геометрии не зависят от DOM.

## Схема

Документ версии 1 содержит:

```json
{
  "version": 1,
  "name": "Пример",
  "nodes": [
    {"id": "a", "type": "INPUT", "x": 80, "y": 100, "label": "A", "value": 1},
    {"id": "b", "type": "OUTPUT", "x": 300, "y": 100, "label": "B", "value": 0}
  ],
  "wires": [
    {"id": "w", "from": {"node": "a", "pin": "out"}, "to": {"node": "b", "pin": "in"}, "points": [{"x": 220, "y": 150}]}
  ],
  "state": {"a": 1, "b": 1}
}
```

`nodes[].value` задаёт значение источника INPUT; выходы остальных компонентов вычисляются. Типы и названия пинов перечислены в `TYPES`. `nodes[].inputs` — необязательное целое 2…32 у AND, OR, XOR, NAND и NOR: столько у компонента входов, по умолчанию 2. `points` — необязательные управляющие точки маршрута; `state` — необязательные сохранённые выходы. Старые документы без этих полей допустимы. Состояние редактора (выделение, масштаб, инструмент, история) в JSON не входит; выделение может содержать несколько компонентов и проводов сразу, поэтому в схеме его нет.

`inputPins(node)` — единый источник имён пинов: у вентилей с настраиваемым числом входов это `a`, `b`, `c`, …, `z`, затем `in27`…`in32`, у остальных типов — список из `TYPES`. Его используют геометрия пинов, валидация проводов, компиляция входов симулятора и отрисовка. Первые два имени остаются прежними, поэтому существующие провода не нужно переписывать.

Геометрия вентиля задаётся числом входов: входы идут с шагом 20 симметрично вокруг `y = 30` и всегда попадают на сетку, корпус растёт от `30 − h` до `30 + h`, где `h = (N − 1)·10 + 15`. При двух входах это прежние значения, поэтому старые схемы выглядят и расположены так же. Метка компонента и рамка выделения (`nodeBox`) следуют за корпусом; рамка остаётся общим источником правды для подсветки и для попаданий в рамку выделения. Входные отрезки рисуются под корпусом: непрозрачная заливка скрывает их концы, когда криволинейный край вентиля приближается к линии пина. У вентилей OR, NOR и XOR вогнутый край не доходит до конца входного отрезка: зазор не больше 5 единиц, у прежних двухвходовых — около 3.

У каждого входного пина не более одного драйвера. Один выход допускает несколько потребителей. Ответвление — отдельный провод с тем же источником и независимым маршрутом; общей редактируемой геометрии ветвей пока нет. Пересечение маршрутов не соединяет цепи.

`validate` проверяет версию, типы, идентификаторы, пины, координаты, ограничение числа элементов/проводов/точек и значения состояния. Дополнительно импорт в интерфейсе ограничен 2 МБ. Проверка локального автосохранения использует тот же валидатор.

Новые необязательные поля могут остаться в версии 1, если старые документы сохраняют смысл. Несовместимые изменения требуют новой версии, явной миграции и тестов на старые файлы. Не меняйте значение существующего поля без миграции.

## Состояние и симуляция

`editor/controller.js` хранит модель схемы отдельно от вычисленных `values`. Флаг `dirty` означает, что электрическая часть изменилась и нужен пересчёт. Перемещение, изменение маршрута, метки и масштабирование не должны устанавливать его. Пауза откладывает вычисление до продолжения.

`simulate(nodes, wires, previous)` начинает с предыдущих выходов и актуальных входных значений. Каждый шаг вычисляет новые выходы из предыдущего шага до устойчивого состояния. Это позволяет обратной связи сохранять состояние RS-триггера. При первом запуске неизвестные внутренние выходы получают X: симулятор не придумывает начальное состояние памяти.

AND, OR, NAND, NOR и XOR считают результат по всему массиву входов любой длины: нуль управляет AND, единица управляет OR, XOR — чётность единиц. Управляющее значение побеждает X и Z, поэтому плавающий вход не превращает AND в 1, а OR — в 0; без управляющего значения результат X. Двухвходная семантика при этом не меняется.

Смена числа входов вентиля — электрическое изменение: состав пинов меняется, провода к исчезнувшим пинам удаляются, флаг пересчёта устанавливается. Это одно изменение истории; метка, маршрут и перемещение его не требуют.

Повтор состояний обнаруживает колебания. Меняющиеся выходы помечаются X с последующим распространением; независимые устойчивые цепи сохраняют значения. На число шагов есть ограничение. Модель не воспроизводит физические задержки или метастабильность.

История хранит пары «модель + значения», максимум 100 изменений. Одно перетаскивание — одна запись истории. Автосохранение использует ключ `web-logisim-v1` в localStorage; экспорт включает схему и вычисленные значения.

## Выделение

`selected` — множество идентификаторов компонентов и проводов; один выделенный элемент открывает панель свойств, несколько показывают состав группы. Рамка выделения (ЛКМ по пустему месту в инструменте «Выбор») считается в координатах схемы: компонент попадает в выделение, если рамка пересекает его габариты, провод — если рамка пересекает его маршрут. Попадания пересчитываются на движении указателя и сразу подсвечиваются; модель при этом не меняется, флаг пересчёта не устанавливается, поэтому выделение не запускает симуляцию и не сбрасывает память. Shift дополняет выделение, обычный щелчок по пустому месту снимает его, Escape и потеря захвата указателя возвращают состояние до рамки.

Перетаскивание выделенного элемента перемещает всю группу: компоненты сдвигаются, а управляющие точки выбранных проводов и проводов, оба конца которых внутри группы, следуют тем же смещением. Провода без управляющих точек следуют за пинами сами. Перенос группы — одно изменение истории и не требует электрического пересчёта.

## Существенные ограничения

- Однобитные сигналы и однонаправленные соединения, без нескольких драйверов на входе.
- Транзисторы — цифровые ключи, не аналоговая модель.
- Нет вложенных схем, многобитных шин, RAM, готовых тактовых компонентов и импорта `.circ`.
- При одновременном снятии запрещённых входов симметричный RS-триггер может перейти в X; корректный set/reset восстанавливает состояние.
- Контроллер связывает инструменты редактора; отдельные модули отвечают за отрисовку, хранение, историю и вид поля.

## Полезные направления дальнейшей работы

Это возможные задачи, а не обещанные функции или утверждённый план:

1. Выделять отдельные инструменты из контроллера по мере усложнения их поведения.
2. Улучшить редактирование общей геометрии ответвлений: сейчас у каждой ветви свой маршрут и общих точек нет.
3. Добавить генератор тактов и последовательностные компоненты с тестами переходов.
4. Спроектировать вложенные схемы и многобитные сигналы с миграцией формата.
5. Включить браузерные проверки в CI с отдельным профилем и артефактами ошибок.

## Производительность и границы кешей

- Симулятор один раз сопоставляет входы с индексами источников и использует массивы значений на шагах распространения. Объект значений по ID создаётся для результата. Синхронная модель распространения и сохранение предыдущего состояния не изменены. Число входов задаёт размер массивов не чаще одного раза на шаг, независимо от числа входов вентиля.
- Валидатор и renderer строят `Map` по ID и входным пинам. Поиск драйвера не перебирает все провода для каждого пина.
- Renderer сохраняет DOM-узлы по ID. Неизменившаяся разметка повторно не присваивается; порядок элементов соответствует модели, включая undo/redo.
- Маршрут рассчитывается один раз для комбинации источника, назначения, координат и управляющих точек. Изменение любого из этих данных инвалидирует запись. Удалённые провода удаляются из кеша.
- Точки ответвлений пересчитываются только при изменении геометрии. Сегменты индексируются по строкам и столбцам; обычное переключение сигнала меняет их цвет, но не геометрию.
- Перемещение обновляет модель сразу, а перерисовки объединяются через `requestAnimationFrame`. При завершении жеста последняя перерисовка выполняется до сохранения.
- Рамка выделения пересчитывает попадания по всем компонентам и маршрутам только во время движения указателя и не трогает модель. Сам прямоугольник рисуется одним элементом `#marquee` без перерисовки схемы.
- История использует `structuredClone`: снимки не разделяют изменяемые объекты с текущей схемой. Хранятся полные снимки (до 100), поэтому история всё ещё потребляет память пропорционально размеру схемы.

Проверка синтаксиса включает каталог `editor/`. Тесты истории и хранения находятся в `tests/editor.test.js`, попадания в рамку выделения и геометрия вентилей — в `tests/geometry.test.js`, таблицы истинности при трёх и более входах и проверка поля `inputs` — в `tests/simulator.test.js`; браузерная проверка дополнительно проверяет, что перемещение одного вентиля сохраняет DOM-узлы незатронутого компонента и провода, рамка выделения на RS-триггере не сбрасывает Q, а смена числа входов перерисовывает символ, удаляет лишние провода и пересчитывает схему.
